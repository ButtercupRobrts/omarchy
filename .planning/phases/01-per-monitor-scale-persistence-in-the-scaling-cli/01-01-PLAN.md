# Plan 01-01: Rewrite scale persistence to target the monitor's own `hl.monitor()` line and preserve configured position in the live `hyprctl eval` apply

## Goal

`bin/omarchy-hyprland-monitor-scaling` persists a scale change to the target monitor's own `hl.monitor()` line in `~/.config/hypr/monitors.lua` and keeps the monitor's configured position when applying live via `hyprctl eval`. The command gains an optional `[monitor]` positional arg (default: focused monitor). Locked decisions D-01..D-05 from `01-CONTEXT.md` are implemented, not relitigated.

<threat_model asvs_level="1">
  <surface>Injection: the `[monitor]` arg selects a monitor whose name is embedded into a Lua string passed to `hyprctl eval` and written into `monitors.lua`. File safety: the script rewrites a user-owned config file.</surface>
  <controls>Retain the existing `^[A-Za-z0-9._-]+$` guard on the resolved monitor name before any Lua embedding (`Refusing unsafe monitor name`, exit 1). The `[monitor]` arg itself is only ever a `jq --arg` value — never shell- or Lua-interpolated. Monitor description/make/model/serial reach awk via `ENVIRON`, never `-v` (backslash-eating hazard in EDID text). Writes are confined to the fixed path `$HOME/.config/hypr/monitors.lua`; no user-controlled path component is interpolated. A timestamped `monitors.lua.bak.<ts>` backup precedes every write, and writes go through the file (`cat tmp > file`, `sed -i --follow-symlinks`) so a symlinked config stays a symlink.</controls>
  <residual>No high-severity findings. EDID-derived description text is match input to awk only; it is never eval'd or written back as code. Live `hyprctl eval` output rules remain runtime-only and are cleared by reload.</residual>
</threat_model>

<assumption_delta_decision>
  The persistence noun changed: previously the shared `local omarchy_monitor_scale` variable (or the literal `output = ""` catch-all) was the primary target of a scale change; now the monitor's own `hl.monitor()` entry — keyed by connector name or `desc:` selector — is primary. Decision: `promote`. The monitor's own entry becomes the system of record for that monitor's scale; the shared variable survives only as a fallback detail for `GDK_SCALE` (nearest integer, updated on every persist path) and as the scale source for monitors that still have no named rule.
</assumption_delta_decision>

<reversibility_gates>
  - Task 1 (script rewrite): code-only change, trivially revertible. Runtime artifacts it creates (appended named `hl.monitor` lines, `*.bak.<ts>` files) remain valid Lua if the code is reverted — they degrade to ordinary per-monitor rules the old code would then ignore.
  - Task 2/3 (test-only): revertible.
  - Cross-phase gate: the `[monitor]` arg (D-03) is costly to reverse once Phase 2's panel and user scripts call it — it is additive and backward compatible, so the gate is "do not ship a Phase 2 caller until this phase's verify is green."
</reversibility_gates>

## must_haves

Truths derived from the phase goal (what must be TRUE when this plan is done):

- A scale change for a monitor rewrites the `scale` field of that monitor's own `hl.monitor()` entry in `~/.config/hypr/monitors.lua` — name-keyed or `desc:`-keyed, single-line or multi-line, inserting the field when absent — and the change survives `hyprctl reload` (SCALE-01, SCALE-04).
- When no entry names the target monitor, a single-line name-keyed `hl.monitor({ output = "NAME", mode = "WxH@R", position = "XxY", scale = N })` line carrying live mode/position is appended, and `local omarchy_monitor_scale` plus the `output = ""` catch-all remain byte-identical (SCALE-01, SCALE-03).
- The live `hyprctl eval` emits `position = "<liveX>x<liveY>"` read from `hyprctl monitors -j`, never `position = "auto"` (SCALE-02).
- A `monitors.lua.bak.<timestamp>` backup exists before every rewrite or append; a symlinked `monitors.lua` is still a symlink afterwards (D-05).
- `omarchy hyprland monitor scaling <scale|up|down> [monitor]` accepts the optional target, defaults to focused, steps `up`/`down` against the TARGET monitor's live scale, rejects unknown names non-zero with no eval and no write, and rejects names failing `^[A-Za-z0-9._-]+$` (D-03).
- The bare `omarchy-hyprland-monitor-scaling` invocation prints exactly the focused monitor's scale — `bin/omarchy-monitor-state`'s 8-line contract and `monitor-state-test.sh` stay green.
- `local omarchy_gdk_scale` and/or literal `hl.env("GDK_SCALE", "N")` update to the nearest integer on every persist path, append included.
- `bash test/shell.d/monitor-scaling-test.sh`, `monitor-state-test.sh`, `monitor-clamshell-scale-test.sh`, `monitor-output-name-test.sh`, and `./test/cli` all pass.

Flagged assumptions (unresolved edge-probe items — surfaced, not silently dropped):

- [SCALE-01, unclassified] Assumed: an empty `monitors.lua` or one containing zero `hl.monitor` rules takes the append path (there is no in-place target); flagged unresolved by the edge probe.
- [SCALE-02, unclassified] Assumed: replaying live x/y pins a monitor whose FILE rule says `position = "auto"` at its current coordinates until the next reload — the known trade-off locked by D-04 (RESEARCH §3); flagged unresolved.
- [SCALE-03, adjacency] Assumed: when the target's clean scale already equals the request, the rewrite is idempotent (same content, backup and audit still happen); when several rules match the target (name + desc:), ALL are rewritten and Hyprland's last-wins semantics decide; flagged unresolved.
- [SCALE-03, empty] Assumed: a `[monitor]` arg absent from `hyprctl monitors -j` (typo, disabled, unplugged) exits non-zero before any eval or write — there is no "empty target" fallback to focused once an arg was given; flagged unresolved.
- [SCALE-03, ordering] Assumed: the rewriter is splice-only — non-matching lines and blocks emit verbatim in original order, and an appended line lands at end-of-file (last-wins makes position immaterial); flagged unresolved.
- [SCALE-04, unclassified] Assumed: `desc:` matching mirrors Hyprland's `matchesStaticSelector` — the trimmed selector must be a prefix of `hyprctl`'s `.description` or of the reconstructed `{make} {model} {serial}` string; flagged unresolved.

must_haves.prohibitions (descriptor-less, flagged-unverified items surviving the prohibition recall pass):

- Never persist a targeted monitor's scale via the shared `omarchy_monitor_scale` variable or the `output = ""` catch-all rule.
- Never emit `position = "auto"` in the live `hyprctl eval` or in an appended line.
- Never write `monitors.lua` via `mv`/rename — write through with `cat tmp > file` or `sed -i --follow-symlinks`.
- Never create `~/.config/hypr/monitors.lua` when it does not exist.
- Never emit multi-line or `desc:`-keyed `hl.monitor(...)` lines — appends stay single-line and name-keyed for the clamshell parser.
- Never eval a monitor rule keyed by `desc:` — the live apply always uses the connector name.
- Never pass monitor description/make/model/serial to awk via `-v` — `ENVIRON` only.
- Never weaken or bypass the `^[A-Za-z0-9._-]+$` monitor-name guard before embedding a name in Lua.
- Never change the stdout shape of the bare invocation, the audit-log field order, or `omarchy-monitor-state`.
- Never add `set -euo pipefail` to the script — keep the existing explicit-guard style.
