# Plan 04-01: `--default-index N` post-`--` flag → `defaultIndex` payload field → `openDmenu` pre-highlighted row, every existing caller byte-identical

## Goal

`omarchy-menu-select` accepts `--default-index N` after the `--` separator (beside `--width`/`--maxheight`), emits an optional integer `defaultIndex` field in the select-mode JSON payload only when the flag was passed, and `Menu.qml`'s `openDmenu` initializes `selectedIndex` from it via a new node-testable `MenuModel.dmenuDefaultIndex` helper — so a caller can pre-highlight a row and Enter selects it. When the field is absent, behavior is byte-identical to today for all 15 verified call sites plus `omarchy-menu-file`'s `"$@"` pass-through and the routed `omarchy menu select` path. Locked decisions D-01..D-07 from `04-CONTEXT.md` are implemented, not relitigated. This is the milestone's only cross-component contract change and lands as one atomic, independently revertible commit.

<threat_model asvs_level="1">
  <surface>CLI→shell boundary: `--default-index` is caller-controlled input crossing argv → JSON payload (`omarchy-shell shell summon`) → QML `selectedIndex`. Tampering surface: malformed values (non-numeric, negative, float, out-of-range) reach cursor state. Confusion surface: a flag-shaped token reaching the pre-`--` option stream would become a menu row and corrupt all callers including stdin-fed ones.</surface>
  <controls>The flag parses only inside the post-`--` loop, so it can never enter the option stream or the `mapfile` stdin fallback (PITFALLS pitfall 2 — the structural mitigation). Perl `int()` produces a real JSON number — no string interpolation reaches QML, and the payload is argv-quoted end to end with no shell re-parse (RESEARCH §3). `MenuModel.dmenuDefaultIndex` floor-coerces and NaN-guards to a non-negative int, and `rebuildDmenuDisplay`'s existing clamp (Menu.qml:596-598) bounds `selectedIndex` to `[0, count-1]` — a hostile or buggy payload can only move the highlight to a different row, never inject markup or wedge the menu (menu rows render `Text.PlainText`, unchanged). The value-required guard exits 1 before any payload is built.</controls>
  <residual>An out-of-range index silently clamps to the last row rather than erroring — accepted per D-04; the existing clamp is the specified behavior. A `--default-index`-shaped token placed *before* `--` still becomes a menu row by design — the contract places it after `--` and docs/menu.md says so. No high-severity findings; this is additive payload plumbing with no new trust boundary.</residual>
</threat_model>

<reversibility_gates>
  - Task 1 (flag + payload + MenuModel helper + openDmenu wiring + stub e2e): implements D-01 — rated `costly`. `--default-index` becomes a public CLI contract documented in docs/menu.md; renaming later means touching docs and every adopting caller (Phase 6's quality menu is the first). Flagged for the record; the decision is locked in CONTEXT.md, no gate inserted.
  - Task 2 (node tests + source pins + e2e expansion + D-05 comment): reversible — test-only changes plus a comment line.
  - Task 3 (docs + sweep + commit): reversible by reverting the single atomic commit.
  - Cross-phase gate: Phase 6 consumes `--default-index 1` to pre-highlight `medium`; this contract must be green here before that phase builds on it.
</reversibility_gates>

## must_haves

Truths derived from the phase goal (what must be TRUE when this plan is done):

- `omarchy-menu-select Pick a b c -- --default-index 1` emits `"defaultIndex":1` in the select-mode JSON payload and still returns the selection through the tempfile handshake (MENU-01, D-01, D-02).
- With no flag, the payload contains no `defaultIndex` key — every existing caller (the 15 verified `bin/` call sites, `omarchy-menu-file`'s `"$@"` pass-through, and the routed `omarchy menu select` path) is byte-identical in behavior (D-02, RESEARCH §4).
- `openDmenu` assigns `selectedIndex` from `MenuModel.dmenuDefaultIndex(payload, dmenuOptions.length)` before `rebuildDisplay()` runs, so the resolved default row is highlighted and Enter activates it via the already-true `cursorActive` (D-03).
- Out-of-range, negative, non-integer, and non-numeric `defaultIndex` values resolve inside `[0, count-1]` and never wedge the menu (D-04 — helper coercion plus the `rebuildDmenuDisplay:596-598` clamp).
- A `defaultIndex` equal to the option count clamps to the last row; `0` highlights row 0 — the boundary semantics are decided, not emergent (adjacency probe, resolved by RESEARCH §6).
- An empty options list yields `selectedIndex` 0 regardless of the flag, and no flag means no payload key (empty/null-input probe, resolved by RESEARCH §6).
- Typing in the filter resets the highlight to row 0 — `defaultIndex` is initial-only, and a comment in `setFilter` records that intent so nobody "fixes" it (D-05).
- `--default-index` with no following value exits 1 with `omarchy-menu-select: --default-index requires a value` on stderr, before any payload is built.
- `docs/menu.md` documents the flag, its payload field, and the initial-only semantics (D-06).
- `bash test/shell.d/menu-test.sh`, `bash test/shell.d/menu-select-test.sh`, and `./test/cli` pass; `./test/shell` shows no failures beyond the 7 pre-existing environmental set.

must_haves.prohibitions (descriptor-less, flagged-unverified items surviving the prohibition recall pass):

- Never accept a positional or pre-`--` form of the flag — every token before `--` becomes a menu row and a positional default corrupts the five stdin-fed callers (pitfall 2, D-01).
- Never emit `defaultIndex` when the flag was not passed — the absent field is the entire back-compat mechanism (D-02).
- Never add a `*)` arm to the post-`--` case — unknown menu args stay silently ignored.
- Never add new clamp or validation logic in QML — `rebuildDmenuDisplay:596-598` is the bounds check (D-04).
- Never re-apply the default after filtering — the `setFilter` reset is intentional, not a bug (D-05).
- Never resolve the index inline in QML — it lives in `MenuModel.js` so node tests cover it (D-03).
- Never touch `omarchy-menu-input`'s arg loop or `mode: "input"` behavior — the field is ignored there naturally.
- Never rewrite `Menu.qml` wholesale — targeted edits only.
- Never change the `# omarchy:args=` or `# omarchy:examples=` metadata — flags live behind `[-- menu args...]` and `test/cli` lints the shape.
- Never split the flag→payload→cursor path across multiple commits — one atomic, independently revertible commit (CONTEXT specifics).
