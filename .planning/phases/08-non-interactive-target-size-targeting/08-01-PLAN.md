# Plan 08-01: Non-interactive `--target <size>` — free-text size → `plan_target` bitrate/floor step-down → `transcode_video_target` two-pass → one overshoot retry → actual-size notification; every refusal dies before menus/notifications. One atomic commit: `bin/omarchy-transcode` + `test/shell.d/transcode-quality-test.sh`.

## Goal

`omarchy transcode <video> [mp4] [res] --target <size>` accepts free-text sizes (`25M`, `1.5G`, `500K`, `25MB`; bare number = MB), derives video bitrate from probed duration (`target×8 ÷ duration × ~0.98 reserve − 192k audio`), auto-steps resolution down the locked 4k→1080p→720p rungs (floors 2000/800/400 kbps) when the budget is tight, two-pass encodes to the budget, retries once on overshoot, and refuses honestly — naming the achievable minimum — below every floor. Locked decisions D-00a..i and D-01..D-10 from `08-CONTEXT.md` are implemented, not relitigated. One atomic, independently revertible commit (AGENTS.md rule + Phase-4/5/6 precedent) confined to the two `files_modified` paths; `transcode_video`, `output_path`, `select_quality`, and every existing helper stay byte-identical (additive-diff constraint while PR #12135 is under upstream review).
