# Plan 03-01: Recompute monitor position on scale change so edge-adjacent monitors stay adjacent, persist it, and derive GDK_SCALE from the densest monitor

## Goal

`bin/omarchy-hyprland-monitor-scaling` recomputes the target monitor's position whenever a scale change alters its logical size: edges touching (or within ~5 logical px of) a neighbor are normalized back to touching on both axes, deliberate gaps are preserved verbatim, growth that would create a new overlap gets a minimal clamp, and any recompute that would produce a new overlap aborts back to the live position. Scale and recomputed position apply in ONE atomic `hyprctl eval` followed by a verify-read, the corrected position persists to the target's own `hl.monitor()` rule via the existing awk rewriter extended with a descending-offset edit list, and `omarchy_gdk_scale` becomes `round(max(all monitor scales))`. Locked decisions D-01..D-09 from `03-CONTEXT.md` are implemented, not relitigated; the algorithm is RESEARCH Q5's numbered spec.

  <controls>The existing `^[A-Za-z0-9._-]+$` name guard (`:96-101`) still gates every name before any eval or awk input. `recompute_monitor_position` emits integer coordinates only — the awk pass formats `XxY` itself (`printf "%dx%d"`), so no user/compositor text reaches the eval position field. `target`/`new_scale`/`tol` reach the recompute awk via `-v` (trusted numerics + charset-guarded name); monitor identity and `OMARCHY_NEW_POSITION` reach the Lua rewriter via `ENVIRON`, never `-v`. The descending-offset edit list computes all splice spans against the untouched `block_nostr` before any `block_orig` mutation. The `monitors.lua.bak.<timestamp>` backup precedes every write; the awk `exit 3` no-match contract and the unreadable/missing-file guards are unchanged. `recompute_monitor_position` is a pure `return`-status function — it cannot `exit` a sourced test context, and it never touches the filesystem or `hyprctl`.</controls>
  <residual>Hyprland fields the eval omits (`sdr*`, `bitdepth`, `vrr`, `cm`, `mirror`, `addreserved`) are still dropped on live apply — `transform`/`mirror`-class state beyond `transform` remains unreplayed (RESEARCH Q8, accepted residual). A pre-existing overlap elsewhere in the layout still fires Hyprland's notification on every reload our write triggers — we never create new ones (D-04) but cannot silence third-party ones. No high-severity findings.</residual>
</threat_model>

<assumption_delta_decision>
  Two refinements resolve RESEARCH open questions against D-08/D-03 rather than changing the decisions. (1) Q4 `position = "auto*"` policy — `promote` the recommendation: the in-place rewriter rewrites `position` only when the recomputed position differs from live `x,y` AND the stored value is not `auto*`; a missing `position` is never inserted (a rule without it is auto-derived every reload — nothing can go stale there; D-08's "rewrite position like scale" covers the only case that can go stale: a literal coordinate). (2) Q5/D-03 tie-break reading — `promote` the minimal-move reading: "ties prefer left/top" = keep the target's own top-left edge fixed (x-axis tie → the `right-of` candidate `x' = m.r`; y-axis tie → the `below` candidate `y' = m.b`). The alternative reading (prefer the neighbor located left/above) pins the opposite edge and moves the target farther; flagged in Flagged assumptions.
</assumption_delta_decision>

## must_haves

Truths derived from the phase goal (what must be TRUE when this plan is done) — edge-probe resolutions are marked [probe-lift] where a CONTEXT/RESEARCH decision supplies the acceptance criterion:

- A monitor whose edge touches (0 px) or sits within ~5 logical px of a neighbor's edge — in EITHER direction, a tiny gap OR a tiny overlap — with a positive shared span on the perpendicular axis, is repositioned so the edges touch exactly at the new scale, on both axes (SCALE-08, D-01, D-02) [probe-lift: SCALE-09 "adjacency" — touching/near-touching edges normalize to touching; they neither merge nor drift apart]. Canonical: HDMI-A-1 `-1200x0`@1.6 (1920 px) → `1.5` lands `-1280x0`; → `2` lands `-960x0`; → `2.5` lands `-768x0`.
- A monitor with a clear gap (> ~5 px) or no shared perpendicular span (corner-graze) keeps its live coordinates EXACTLY — deliberate gaps are never normalized, never proportionally rescaled (SCALE-08, D-06) [probe-lift: SCALE-09 "empty"/"ordering" — a monitor with zero adjacency candidates is a defined case, not an error: verbatim keep, deterministic output].
- A single-monitor array recomputes to the live position unchanged — the empty-neighbors case is the no-op case (SCALE-08) [probe-lift: SCALE-10 "empty" analog for geometry].
- A sandwiched monitor preserves adjacency to the neighbor sharing the largest boundary; an equal-share tie keeps the target's own top-left edge fixed; no third monitor is ever moved; and the sacrificed side is recorded in the audit log as a `drop-<side>` note token (SCALE-08, D-03) [probe-lift: SCALE-09 "ordering" — deterministic, stable pick specified].
- When growth would overlap a NON-adjacent monitor, a minimal clamp shifts the target just enough along the shared axis to separate (SCALE-08, D-05); when ANY recompute result would create a new positive-area overlap, the position change is discarded entirely — live coords apply and the audit log records `note=abort` (D-04). A recompute never produces a worse state than doing nothing [probe-lift: SCALE-10 "adjacency" — touching edges are zero-area and legal; ≥1 px positive-area intersection is an overlap].
