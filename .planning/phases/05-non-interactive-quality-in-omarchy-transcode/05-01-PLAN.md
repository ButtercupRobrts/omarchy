# Plan 05-01: Optional 4th positional `quality` → locked CRF/fps tier tables → `-high`/`-low` filename suffix → `[[ -e || -L ]]` dedupe, medium byte-identical

## Goal

`omarchy transcode INPUT FORMAT RESOLUTION [QUALITY]` accepts an optional quality arg ∈ `high|medium|low` that selects the locked per-codec tiers — x264 CRF 18/23/28, x265 CRF 20/24/28, gif fps 15/10/5 — where `medium` or an omitted arg reproduces today's encoder flags byte-for-byte, non-default tiers append `-high`/`-low` to the output filename, pictures reject the arg before any notification, and an existing output dedupes to `-2`/`-3` so no launch path can hit ffmpeg's stdin overwrite prompt or a silent detached abort. Locked decisions D-00a..d and D-01..D-04 from `05-CONTEXT.md` are implemented, not relitigated. One atomic, independently revertible commit (AGENTS.md rule + Phase-4 precedent).

<threat_model asvs_level="1">
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller argv → `main()` | positional quality value, input path, format, and resolution are caller-controlled; the `file` MIME verdict on the input is attacker-craftable |
| `main()` → `ffmpeg`/`magick` argv | validated values cross into encoder command lines |
| `output_path()` → filesystem | the computed output name becomes a real file written next to the input |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Tampering | `output_path()` dedupe loop | high | mitigate | `while [[ -e $candidate \|\| -L $candidate ]]` — the `-L` covers dangling symlinks that `-e` misses; without it ffmpeg would write through the link to an unrelated target (the one real data-loss edge) |
| T-05-02 | Tampering | quality arg → filename/argv | medium | mitigate | `high\|medium\|low` whitelist enforced in `main()` before `output_path` sees the value — only the literals `high`/`low` can ever reach the filename; `-`-leading values can't survive the `case`; no traversal or flag injection |
| T-05-03 | DoS | ffmpeg stdin overwrite prompt on detached/keybind launch | high | mitigate | dedupe removes the only interactive surface — ffmpeg never sees an existing target, so no `[y/N]` read can hang a tty-less launch or die silently after the start notification; no overwrite-forcing flag is added (D-01) |
| T-05-04 | Tampering | TOCTOU between dedupe check and ffmpeg open | low | accept | a file materializing in the gap degrades to today's prompt/refuse behavior — never a silent clobber; the window is inherent to any check-then-write |
| T-05-05 | Info/Tampering | `file` MIME output → `media_type` glob | low | accept | attacker-controlled MIME strings only feed `image/*`/`video/*` glob matching and an error echo — no eval, no arithmetic |
| T-05-06 | Tampering | `format` value → filename extension | low | accept | a `--`-passthrough like `a/b` yields `stem-1080p.a/b`, `-e` is false, ffmpeg fails on open — pre-existing, quoted, no worse than today |

No package-manager installs in this phase — the `T-05-SC` supply-chain row is not applicable.
</threat_model>
