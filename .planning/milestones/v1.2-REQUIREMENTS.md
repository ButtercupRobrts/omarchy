# Requirements Archive: v1.2 Target-Size Transcode

**Archived:** 2026-09-18
**Outcome:** 6/6 requirements Complete

## v1.2 Requirements — Final Status

### Size Targeting

- [x] **SIZE-10**: `--target <size>` parses free-text sizes into integer bytes and two-pass encodes to the byte budget — validated end-to-end; actual size reported via the SIZE-02 notification mechanism
- [x] **SIZE-13**: Resolution auto-step-down — planner picks the highest fitting rung; filename and both toasts name the effective resolution; below-floor runs refuse naming the achievable minimum
- [x] **SIZE-14**: Audio stays fixed `-b:a 192k`; budgets that can't fit audio plus a viable video bitrate refuse early, pre-notification, naming the minimum
- [x] **SIZE-15**: Over-target outputs re-encode once at a tightened bitrate (scaled by overshoot ratio); actual size reported either way — never a silent loop

### Interactive

- [x] **MENU-02**: `Custom size…` row on the mp4 quality menu → `omarchy-menu-input` → same parser/planner — re-prompts once with a hint on bad input, cancels cleanly on Esc; UAT passed live

### Safety / Refusals

- [x] **SAFE-02**: `--target` mutually exclusive with positional quality (error naming both); refuses gif and pictures; fails fast before the start notification on missing/unparseable values and probe failure — plus a post-implementation hardening: sentinel branch format-gated on mp4 (WR-01)

## Requirement Amendments

- **Decimal units**: all user-facing sizes are SI decimal MB (1 MB = 1,000,000 B) — parser, canonical tokens, refusal minimums, estimates, and the completion notification. Adopted post-UAT when the IEC/MiB interpretation produced apparent ~16 MB overshoots against file-manager displays and decimal upload limits (`4d422ffe`).
