# Plan 02-01: Per-bar monitor targeting for SCALE pills plus per-monitor scale display in the DISPLAYS section

## Goal

Each `omarchy.monitor` panel instance resolves the screen of the bar window hosting it (the `QsWindow` attached property — the same source `Bar.qml`'s `slotScreenName` uses) and aims its SCALE pills, `setScale` call, and section header at that monitor instead of the globally focused one. The DISPLAYS section shows each monitor's current scale (`HDMI-A-1 · 1.6x`), a non-preset scale surfaces as a dynamically inserted "current" pill, and single-monitor setups keep working. Per-display scale reaches the panel via a one-word `scale` addition to `omarchy-monitor-state`'s line-7 jq projection. Locked decisions D-01..D-06 from `02-CONTEXT.md` are implemented, not relitigated.

<threat_model asvs_level="1">
  <surface>Injection: a connector name (`screen.name`) flows from compositor state into a CLI argv element that the Phase 1 script embeds into a Lua string and a user config file. Input: the displays JSON array is parsed into row objects rendered as text.</surface>
  <controls>`Process.command` is a direct argv list — dropping the `bash -c` wrapper removes shell interpretation entirely; `ownScreenName` is appended only as a discrete array element, never string-interpolated. The Phase 1 CLI re-validates the resolved name against `^[A-Za-z0-9._-]+$` before any Lua embedding and passes it to jq via `--arg`. Every Text element that renders a monitor name or scale keeps `textFormat: Text.PlainText` — connector names and scale values can never be interpreted as markup. `parseDisplays` already wraps `JSON.parse` in try/catch and coerces non-arrays to `[]`. `screen.name` is compositor-supplied (not user-editable text), and `pickPanelSlot` already proves it byte-matches `hyprctl`'s monitor names.</controls>
  <residual>A mirrored screen's bar pills target a mirror output that `hyprctl monitors -j` (the CLI's source) drops — the CLI exits 1 "No such monitor", `actionProc` completes and only `refresh()` runs: a silent no-op, accepted per Flagged Assumptions. No high-severity findings.</residual>
</threat_model>

The additive JSON field keeps one Process and one update path (no second poll racing `stateProc`), and the 8-line positional contract is untouched — line count and ordering are identical, so the init rationale (don't destabilize the contract) is satisfied rather than violated. ## must_haves

Truths derived from the phase goal (what must be TRUE when this plan is done):

- Each bar-hosted `omarchy.monitor` panel instance resolves its hosting screen via the `QsWindow` attached property and aims `scaleValues`, `activeScaleIndex`, `effectiveScale`, and `setScale` at that screen's monitor — pills on the `HDMI-A-1` bar change `HDMI-A-1`, pills on the `eDP-1` bar change `eDP-1` (SCALE-05, D-05).
- `setScale` invokes `omarchy-hyprland-monitor-scaling` as a direct argv list with `ownScreenName` appended only when non-empty — empty degrades to the CLI's focused-default — so a panel-initiated change persists to the correct `hl.monitor()` line via Phase 1 and survives reload (SCALE-05; roadmap success criterion 3).
- The SCALE header's right-aligned text reads `ownScreenName · ownScalex` whenever `ownScreenName` is known — `SCALE — HDMI-A-1 · 1.6x` — with no display-count gate (D-03).
- Each DISPLAYS row renders `name · N.Nx` (plus `· focused` when focused), the scale suffix gated on `enabled` and non-empty normalization, and clicking a row still runs the stock enable/disable toggle only (D-01, D-02, SCALE-06).
- A current scale that matches no preset appears as a dynamically inserted, correctly-ordered pill that `matchingScaleIndex` marks active; a preset-matching scale adds no pill (D-04).
- With `displays.length == 1` there is no DISPLAYS section or separator, the SCALE row and header still work, and keyboard nav is unchanged (SCALE-07).
- `bin/omarchy-monitor-state` still emits exactly 8 lines in the same order; line 7's per-monitor objects carry `scale` as a new last field (D-06).
- `focusedMonitor` and `monitorScale` retain focused-monitor semantics: brightness argv, `stateIpc` `focusedMonitor`/`scale` fields, and line 5/6 parsing are byte-identical in behavior.
- `bash test/shell.d/monitor-state-test.sh`, `bash test/shell.d/monitor-test.sh`, `bash test/shell.d/monitor-scaling-test.sh`, and `./test/cli` all pass; `./test/shell` shows no new failures.

must_haves.prohibitions (descriptor-less, flagged-unverified items surviving the prohibition recall pass):

- Never repurpose `focusedMonitor` or `monitorScale` to own-screen semantics — add parallel `own*` properties instead (the IPC `state()` result must not become instance-dependent).
- Never rewrite `Panel.qml` wholesale — it contains raw Nerd Font glyphs; targeted edits only.
- Never build the scaling command with `bash -c` or string interpolation — direct argv elements only.
- Never snapshot `ownScreenName` into a static/computed-once value — it must stay a bound property that re-evaluates when `QsWindow` attaches.

- Never gate the SCALE header or pill targeting on `enabledDisplayCount`/`displays.length` — own-screen identity is independent of how many displays exist.
