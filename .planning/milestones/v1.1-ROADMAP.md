# Milestone v1.1: Transcode Quality & Size Feedback

**Status:** ✅ SHIPPED 2026-09-16
**Phases:** 4-7
**Total Plans:** 4

## Overview

Milestone v1.1 added a quality step and size feedback to `omarchy-transcode` in four atomic phases: `omarchy-menu-select` gained a `--default-index` flag for pre-highlighted rows, `omarchy-transcode` gained an optional 4th positional quality arg with locked per-codec tier tables (x264 CRF 18/23/28, x265 CRF 20/24/28, gif 15/10/5 fps) where `medium` reproduces prior flags byte-for-byte, the interactive flow gained a `Select quality` menu with `~N MB` mp4 estimates and fps gif rows, and the completion notification now reports the actual output size.

## Phases

### Phase 4: Menu `defaultIndex` plumbing

**Goal**: `omarchy-menu-select` accepts `--default-index N` after `--`, emits `defaultIndex` in the select-mode JSON payload, and `Menu.qml`'s `openDmenu` initializes `selectedIndex` from it — with every existing caller byte-identical in behavior
**Depends on**: Nothing (first milestone phase)
**Requirements**: MENU-01

Plans:

- [x] 04-01: `--default-index` post-`--` flag → `defaultIndex` payload field → `openDmenu` pre-highlight via `MenuModel.dmenuDefaultIndex`, with stub e2e + node coverage and docs

**Goal**: `omarchy transcode INPUT FORMAT RESOLUTION [QUALITY]` accepts an optional quality arg that selects locked per-codec tiers — where `medium` or omitted reproduces prior encoder flags byte-for-byte, non-default quality appends a filename suffix, and output collisions follow a deliberate non-interactive-safe policy
**Depends on**: Nothing
**Requirements**: QUAL-02, QUAL-03, SAFE-01

Plans:

### Phase 6: Interactive quality prompt + size estimates

**Goal**: The video transcode flow gains a `Select quality` step after format+resolution whose rows carry `~N MB` estimate subtexts for mp4 (ffprobe duration × tier bitrate table + 192k audio) and fps subtexts for gif, with `medium` pre-highlighted — pictures see no new prompt
**Depends on**: Phase 4, Phase 5
**Requirements**: QUAL-01, SIZE-01

Plans:

- [x] 06-01: `select_quality` + probe/token/kbps/estimate helpers + `type == video && -z $quality` main() block, dual-mode/ffprobe stub harness + degrade matrix

### Phase 7: Completion-size notification + docs

**Goal**: The transcode completion notification reports the actual output file size, closing the estimate→actual loop, and all user-facing docs/metadata are in sync
**Depends on**: Phase 6

## Milestone Summary

**Key Decisions:**

- Named quality tiers over raw CRF controls (core-value alignment; CRF is logarithmic and meaningless to expose)
- `medium` reproduces pre-change encoder flags byte-for-byte — zero behavior change on the default path
- MiB-scale arithmetic labeled `MB` for both estimate and actual (same scale, matching roadmap examples)
- Estimates deliberately approximate (`~N MB`, ±2×); the completion notification carries the true size to close the calibration loop
- gif rows show fps, never size estimates (20–30× content spread would make a table misleading)
- `--default-index` is initial-position-only; typing resets the highlight (`setFilter` → `selectedIndex = 0`)

**Issues Resolved:**

- `0 MB` toast for sub-1 MiB outputs → `<1 MB` band (972a1bba)
- `%d` flooring understated sub-10 MiB estimates → `%.0f` rounding (8d52171b)
- Non-finite `--width`/`--maxheight` emitted invalid JSON → regex guard matching `defaultIndex` arm (2211f8c3)
- Orphan `Transcoding video…` toast on bad positionals → format/resolution validation hoisted into `main()` (c1947f8d)

**Issues Deferred:**

- TOCTOU between output dedupe and ffmpeg open (accepted — degrades to today's prompt/refusal)
- `positional[5]+` silently dropped (pre-existing leniency)
- `.gif` inputs classify as `image/gif` → picture arm (pre-existing)
- Duplicated tier constants between `transcode_video` and `quality_token` (deliberate inside the PR #6698 conflict window; both test-pinned)
- Notifications omit the quality tier (only size is reported)

**Close-out:**

- Milestone audit: `passed` — 7/7 requirements satisfied, all phases Nyquist-compliant, cross-phase integration verified (`.planning/v1.1-MILESTONE-AUDIT.md`)
- UAT: phases 5, 6, 7 all passed in the running UI
